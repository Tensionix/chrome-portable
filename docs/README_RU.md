# Audion Chrome Portable

Собирает портативный Google Chrome, обновляет собранное, держит в свежем виде
Chrome++ и умеет положить в сборку сертификаты НУЦ Минцифры вместе с двумя
врапперами - поставить и снять. В Windows ничего не устанавливается:
standalone-установщик распаковывается, а не запускается.

## Как это устроено

```text
ChromeStandaloneSetup64.exe (~120 МБ)
└── Chrome.7z
    └── Chrome-bin\        →  <сборка>\App\
          chrome.exe
          <версия>\ и всё остальное
```

Google время от времени перекладывает `Chrome.7z` внутри установщика, поэтому
программа не полагается на фиксированный путь: она обходит кандидатов и пробует
их распаковать, пока не найдёт нужный.

Портативность даёт Chrome++: рядом с `chrome.exe` кладётся его `version.dll`.
Запущенный процесс после этого несёт `--portable` и `--user-data-dir`, профиль
уходит в `Data` рядом с `App`, кэш - в `Cache`. Установленный в системе Chrome
при этом не затрагивается: проверено на машине, где он работал одновременно.

Обёртка выбирается: Chrome++, прокси библиотека
([neyrostalker/proksi-biblioteka](https://gitflic.ru/project/neyrostalker/proksi-biblioteka)
на GitFlic, релиз тянется по публичным страницам без токена) . Прокси библиотека блокирует запись в реестр вместо стирания ветки на
выходе и не вызывает нареканий у Microsoft; разрядности у неё только x86 и x64.
Разбор обеих обёрток и проверка на VirusTotal - в
`docs/CHROME_PLUS_AND_DEFENDER.md`.

Chrome++ — давно существующий и уважаемый проект с открытым кодом; антивирус
иногда ошибочно принимает его `version.dll` за угрозу. Почему это ложное
срабатывание и как программа обходит его во время сборки —
в [CHROME_PLUS_AND_DEFENDER.md](CHROME_PLUS_AND_DEFENDER.md).

Готовая сборка:

```text
Google Chrome Portable\
  App\                          браузер, version.dll, chrome++.ini
  Data\                         профиль
  Cache\                        кэш
  Certificates\                 сертификаты Минцифры и два враппера
  Google Chrome Portable.cmd    запуск
  Portable-Build.json           какие версии внутри
```

## Интерфейс

Корневое окно - свитчер из четырёх вкладок. Команда с параметрами
разворачивается прямо на вкладке: своя кнопка запуска, названная действием, и
свои поля. Служебные операции стоят строкой над вкладками. Выбор - кнопками:
выбранная залита полупрозрачным синим, невыбранная контурная. Подписи короткие,
объяснение живёт в тултипе.

## Что делают команды

| Вкладка | Команда | Что делает |
| --- | --- | --- |
| `Установка` | `Собрать` | Скачивает установщик и Chrome++, публикует сборку в папку назначения. |
| `Обновление` | `Проверить` | Сравнивает опубликованные версии с версиями сборки. Не скачивает ничего. |
| `Обновление` | `Обновить` | Заменяет `App` в сборке из `Источника`, сохраняет `Data` и `Cache`. |
| `Обновление` | `Chrome++` | Меняет `version.dll` и `chrome++.ini`, браузер не трогает. |
| `Сертификат` | `Проверить` | Показывает, доверяет ли пользователь сертификатам. Ничего не меняет. |
| `Сертификат` | `В сборку` | Кладёт оба файла и врапперы в сборку. Доверия не добавляет. |
| `Сертификат` | `Установить` | Добавляет их в хранилища текущего пользователя. |
| `Сертификат` | `Отозвать` | Удаляет ровно эти два по отпечатку. |
| `Обслуживание` | `7-Zip` | Проверяет распаковщик и кладёт портативную копию в папку проекта. |

## Обновление

Версия опубликованного Chrome читается из API истории версий Google - проверка
стоит одного небольшого запроса, установщик не качается. Версия собранного
берётся из самой папки (`FileVersion` у `chrome.exe` и у `version.dll`), поэтому
обновить можно и чужую сборку.

Обновление идёт **на месте**: сборка меняется в той папке, на которую указывает
`Источник`, а не публикуется заново в папку назначения - та нужна для новых
сборок. Если в `Источнике` сборки нет, программа смотрит в `output\Portable`.
`App` заменяется через переименование: старая папка отходит в сторону, на её
место встаёт новая, и только потом старая удаляется. Если браузер запущен и
переименовать нельзя, операция об этом говорит и сборку не трогает.

Chrome++ обновляется вместе с браузером и отдельной командой. Список файлов
выпуска берётся через API GitHub, а при любой его ошибке - со страниц
`releases/latest` и `releases/expanded_assets/<tag>`, где квоты нет: анонимных
запросов к API всего 60 в час.

## Сертификаты Минцифры

Chrome на Windows смотрит в хранилища сертификатов **текущего пользователя**
наряду со своим собственным корневым списком. Поэтому сертификаты ставятся
командой

```bat
certutil -addstore -user -f Root russian_trusted_root_ca.crt
certutil -addstore -user -f CA  russian_trusted_sub_ca.crt
```

Это не требует прав администратора, не затрагивает другие учётные записи и
снимается обратно по отпечатку. Обе операции после выполнения перечитывают
хранилище и не верят коду возврата на слово.

Отпечатки зафиксированы в программе:

- `Russian Trusted Root CA` - `8FF915CC…AEC2F`, хранилище `Root`;
- `Russian Trusted Sub CA` - `335D43F5…8A01`, хранилище `CA` (промежуточное).

Честная оговорка: полностью «внутри папки» сертификат жить не может - Chrome на
Windows читает системные хранилища, а не файл рядом с собой. Поэтому доверие
сделано отдельным, обратимым шагом, а не частью сборки.

Яндекс.Браузеру это не нужно: у него поддержка НУЦ встроена. Для него есть
отдельная программа - Audion Yandex Portable.

## Следы в системе

Chrome держит счётчики в `HKCU\Software\Google\Chrome`. Стереть эту ветку при
выходе сборка умеет, но по умолчанию **не** делает: ветка общая с установленным
Chrome, а он есть на большинстве машин. Включайте галку только там, где обычного
Chrome нет.

## Требования

- Windows, портативный Python в `runtime\` (идёт с проектом).
- `tools\7zip\bin\7za.exe` - ставится командой `7-Zip` со вкладки `Обслуживание`.
- Около 120 МБ на загрузку и до 700 МБ на распаковку и публикацию.
